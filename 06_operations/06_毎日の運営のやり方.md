# 毎日の運営のやり方

> **同期元:** `06_毎日の運営/06_毎日の運営のやり方.docx` / 2026-09-16 v1.1

> 通常は自動、例外だけ人が確認する運営を目指す

## 運営の基本

通常案件はシステムで自動処理し、未割当、事故、キャンセル、応援、クレーム、赤字・低採算等の例外だけ人が確認する運営を目指します。

## 毎朝

- 今日の予約。
- まだ担当が決まっていない案件。
- 協力業者の休み・欠勤。
- 応援依頼。
- 赤字・低採算で保留中の応援案件。
- 重大事故・未解決クレーム。

## 日中

- 新規予約。
- 日時変更・キャンセル。
- 問い合わせ。
- 応援依頼。
- 完全紹介の新料金承認待ち。
- 追加作業の承認待ち。
- 事故・施工中トラブル。

## 夕方

- 完了していない案件。
- 作業前後写真の不足。
- 作業時間・試運転結果。
- 現金受領記録。
- 応援案件の支払条件・差額・例外補填。
- 翌日の未割当案件。

## 毎週

- 売上・案件数。
- 協力業者の稼働。
- 辞退率・応援回数。
- 応援案件の平均残額。
- 赤字・低採算でブロックされた案件数。
- クレーム・再施工。
- 未精算・未解決案件。

## 毎月

- 1件あたりの利益。
- 広告費。
- LINE等の通信費。
- 再注文率。
- 協力業者数・空き。
- 応援施工の成立率と採算。
- 例外補填額。
- 次の地域へ広げてよいか。

## 案件価格保護の例外処理

応援施工で `customer_price_locked - support_payout - platform_fee - その他変動費 + support_subsidy` が最低採算基準を下回る場合、自動成立させません。

原則として次の順で検討します。

1. 別の応援業者を探す。
2. 元の担当業者が差額を負担できるか確認する。
3. 事故・運営都合等に限りHOMENECTの例外補填を検討する。
4. 完全紹介へ切り替える場合は、新しい料金をお客様へ提示して承認を取る。

## 誰が何を決めるか

| 内容 | 原則 |
| --- | --- |
| 通常の予約・割当 | システム / 設定済みルール |
| 応援案件の通常成立 | 設定済み採算基準 |
| 赤字・低採算の例外 | 運営責任者 |
| 例外補填 | 事業責任者 / 権限者 |
| 返金・補償 | 運営責任者 |
| 重大事故 | 運営責任者へ即時連絡 |
| 協力業者停止 | 事実確認後に運営判断 |
| 通常価格の変更 | 各協力業者が独立して決定・登録 |
| HOMENECT料金/手数料 | 事業責任者が正式料金表を更新 |
| エリア変更 | 供給・実績を見て運営判断 |

## 協力業者が辞めるとき

1. 今後の予約を確認。
2. 必要な案件を他の協力業者へ引き継ぐ。
3. 応援か完全紹介かを明確にし、料金変更がある場合はお客様へ事前確認。
4. お客様へ必要な案内。
5. 未完了・未精算を確認。
6. システムの顧客情報アクセスを停止。
7. 保管義務のある記録はHOMENECT側で保持。
