## モックアップの目的

開発前に「実際に誰がどんな順番で使うのか」を共有し、完成後の認識違いを減らします。画像は完成デザインの固定ではなく、操作と情報の優先順位を確認するための資料です。

## お客様向け画面

| 画面 | 主な内容 |
| --- | --- |
| TOP | サービス選択、エリア、料金の入口 |
| 料金・空き | サービス、料金、日時 |
| 機器・写真 | エアコン情報、型番、写真 |
| 予約確認 | 日時、料金、支払い、取消条件、契約主体 |
| 予約完了 | 予約番号、当日の案内 |
| 予約一覧 | 予約済み・完了・取消 |
| 作業履歴 | 写真、作業内容、担当 |
| 再予約 | 前回と同じ内容で予約 |

## 協力業者向け画面

| 画面 | 主な内容 |
| --- | --- |
| ホーム | 今日の案件、未対応、受付ON/OFF |
| 新規案件 | 日時、地域、作業、報酬条件 |
| 案件詳細 | 受ける/断る |
| 今日の仕事 | 受諾済み案件 |
| 作業報告 | 前後写真、開始・終了、異常、試運転 |
| 応援依頼 | 理由、日時、地域、条件 |
| スケジュール | 空き、休み、受付可能数 |
| 売上・精算 | 案件と金額の確認 |

## 運営向け画面

- 今日の予約・未割当。
- 顧客・機器。
- 協力業者・対応地域。
- 応援依頼。
- 事故・クレーム。
- お知らせ設定。
- 売上・案件数・通信費。

## 応援の画面

1. 元の担当が「応援依頼」。
2. 日時・地域・作業・報酬条件を表示。
3. 対応可能な協力業者へ案内。
4. 応援業者が受諾。
5. 施工。
6. 次回の優先担当は自動変更しない。

## LINEからの入口

LINEのメニューやメッセージから同じWeb画面へ移動できるようにします。LINE内で使えない機能があっても、通常ブラウザで主要業務を完了できる設計にします。

## 画面づくりの共通ルール

- スマホで見やすい。
- 1画面に詰め込みすぎない。
- 一番重要な操作を大きく表示。
- 戻る・キャンセルを分かりやすくする。
- 専門用語を減らす。
- エラー時に次に何をすればよいか表示する。
